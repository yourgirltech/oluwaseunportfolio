How I build AI systems

Six rules I hold every agent to

Each rule is in my code, and each one links to the repo where you can check it.

Deterministic first, model second

A rule engine scores the claim before any LLM sees it. The model explains and recommends from that grounded output; it never invents the facts.

Clyra · 01-analyzer

Approval is structural

"A human approves anything consequential" is enforced by the router's rule table and by raise guards in the orchestrator. It doesn't depend on a prompt.

Foresight · commander.py

Routers are pure functions

The Commander has no tools and generates no text. Because it only reads state and returns a decision, I can fuzz it: one rule block runs against 23,328 states.

Foresight · commander tests

Fail closed

If a model returns JSON I can't parse, the claim goes to human review and the quote request goes to a sales call. Uncertainty always routes to a person.

Healthcare revenue cycle · multi-tenant SaaS · Python

Foresight

phases 0–5 built

An AI platform for clinics that handles insurance eligibility, prior authorization, card scanning, cost estimates, claims, appeals and patient reminder calls. Many clinics share one deployment, and none can see another's data.

Engineering decisions

  • Commander pattern for orchestration. A pure router walks an ordered rule table, terminal guards first, then dispatches to specialist agents: eligibility, prior auth, OCR, coordination of benefits, cost estimate, appeals and voice reminders.
  • Specs before code. Every agent has a numbered spec in docs/agents/, and new rule blocks are added as separate branches so earlier rules and their tests stay untouched.
  • Care-safety invariants are hard-enforced. For example, an emergency prior-auth case can never be auto-advanced; the orchestrator raises before that happens.
  • Claude for reasoning and vision. The Anthropic SDK powers the reasoning agent and insurance-card OCR, with images validated by Pillow before the vision call and scan images purged on a schedule.
  • Voice reminders with consent. FastAPI routes drive n8n and Vapi calls, render variables in each clinic's own timezone and cancel calls when consent is revoked.

Insurance Claims RAG Pipeline

private build

A first-notice-of-loss pipeline. It checks a new claim against the actual wording of the customer's policy, scores damage from photos and sends an adjuster a decision packet to approve.

Engineering decisions

  • Retrieval scoped by tenant. The incident description is embedded with Gemini text-embedding-004, then pgvector returns the 8 nearest active policy chunks for that tenant or shared documents.
  • Two grounding sources merged. The structured policy record (status, limits) and retrieved policy language are combined before the coverage call.
  • Typed verdict with citations. The model must return coverage_status, confidence, reasoning and cited_sources as strict JSON.
  • Vision only when needed. Photo damage scoring runs only if photos were submitted; otherwise a default is set so the packet shape stays the same.
  • Adjuster approves or flags. Approved claims are saved and confirmed to the policyholder, while flagged claims escalate to a senior adjuster.

Fail-closed parsing, from the pipeline

try {
  parsed = JSON.parse(cleaned);
} catch (e) {
  parsed = {
    coverage_status: 'needs_review',
    confidence: 0,
    reasoning: 'Failed to parse model output - defaulting to human review.'
  };
}

If the model's output is malformed, the claim goes to a person instead of being guessed at.

Healthcare billing · agent system · Python

Clyra

MVP · synthetic data

A claims operations assistant for US billing teams. Eight agents analyze claims, explain risk, recommend next steps, chase payers and escalate. It uses only synthetic data, so the demo never touches real patient records.

Engineering decisions

  • Chose a Commander router over a LangGraph node graph, so every routing decision can be audited from one rule table.
  • Each agent does one job and hands control back: analyzer, reasoning, recommendation, follow-up, reminder, escalation and a free-form assistant.
  • The analyzer calls a deterministic risk engine and produces the canonical issue list and risk level that every later agent builds on.
  • Recommendation approval is stored in the schema, with Alembic migrations for approval fields, escalations and payer reminders.

Tool-using agent · production e-commerce

MO, the Style & Glitz Assistant

live

A shopping assistant on a live luxury store. It answers from the real catalog and store policies, guides customers through checkout and looks up a signed-in customer's own orders.

Engineering decisions

  • Model fallback. Gemini is the primary model and Claude Sonnet is the backup. If both fail, a fixed message points customers to the human team.
  • Least-privilege tools. Order, profile and line-item tools call Supabase with the customer's own access token, so RLS decides what the agent can see. There's no service key in the agent.
  • Login-aware prompting. If the visitor isn't signed in, the agent is told not to try any lookup and to send them to /login.
  • Grounding rules. Prices, stock and certification come only from tool output, and the agent may never guess why a payment failed.

Logistics platform · Next.js

Trackora

frontend + 5 workflows

A marketing site, customer tools and an ops dashboard for a freight business: AI-narrated tracking, a quote chat that escalates to a booked call, and dashboards for shipments, tickets and leads.

Engineering decisions

  • One architecture rule for every feature. Side effects go through a Next.js API route to an n8n webhook whose URL lives only in server env. Plain reads go straight to Supabase.
  • The quote chat sends the full history on every turn, so a conversation can escalate to "needs a call" on its fifth message, not only its first.
  • The call form pre-fills itself with the customer's details and a summary of the conversation.
  • Five single-purpose workflows share one Supabase schema, so an event written by one triggers another.

Fintech · React + Supabase

FinanceFlow

live

A personal finance app that adapts to how involved you want to be, works the moment you sign up and never shows a number it can't back up.

Engineering decisions

  • Envelope budgeting: money is reserved the moment a budget is set, rather than reconciled later.
  • Natural-language entry: Quick Add parses "Lunch 15" into a category and amount. Bank statements can be imported.
  • Insights computed locally with no external API, plus a Claude assistant for free-form questions about your real numbers.
  • Onboarding changes the product: picking Simple, Planner or Power User reshapes the dashboard and navigation.
  • Custom SMTP through Resend, so auth emails aren't limited by Supabase's shared sender. Supports 11 currencies and regions.
